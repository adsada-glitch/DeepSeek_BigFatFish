# 05 · 部署与调参

假设你已经有：能收发 QQ 消息的桥接程序、一个能调工具的模型接口。

## 一、最小可用（半天）

只上"记忆内核 + 每轮注入"，不做检索、不做可视化。

```
1. 放好 memory-core.mjs
2. 配一个目录存状态：state/memory/
3. 桥接启动时 createMemory({ dir })
4. 唤醒提示词里加一段：buildMemoryBlock(key)
5. 给模型开两个工具：fact_append / fact_forget
```

**验收**：聊几轮之后，`memory-state.json` 里出现条目，且下一轮提示词里能看到。

如果一周后一条都没有，九成是**"该记什么"只写在角色卡里**，模型没看见。把纪律塞进每轮提示词（见下）。

## 二、加日记（半天）

```
1. 每天凌晨跑一次：扫当天消息 → 抽关键词 → 写 diary/YYYY-MM-DD.md
2. 给模型一个只读工具：diary_search(query)
```

**验收**：问"上周三我们聊了什么"，她能搜到。

注意：日记由脚本写，不让模型写。模型会编，脚本不会。

## 三、加检索层（1~2 天）

```
1. 放好 memory-retrieve.js（或自己的实现）
2. 桥接里改注入：小库按权重、大库按对话挑
3. 加一个开关：memory.retrieval = "query" | "weight"
```

**验收**：活跃记忆超过阈值后，注入块的表头从"全部"变成"按当前话题挑的"，且每轮 token 明显下降。

**灰度**：先只改私聊，群聊保持现状一周。

## 四、加可视化（半天）

```
1. 起 memory-sea 服务（零依赖，默认 4173）
2. 写导出脚本：桥接状态 → data/qq.json
3. 配主题表（务必改成自己的词）
```

**验收**：能看到自己的聊天变成星空，簇名是人话。

不需要就跳过——它只影响"你能看见"，不影响"她记得"。

## 每轮提示词里必须有的两段

**记忆纪律**（约 100 字）：

```
值得长期留着的事（约定、偏好、你们之间的梗、被纠正过的话）
→ 记一条，一句话说清；改口或说记错了 → 作废旧的。
不记流水账。
```

**时间感**：

```
认识第 N 天；现在几点；上次说话是多久前。
```

这两段是"体感"的主要来源，比多记 50 条记忆有用。

## 灰度的三条规矩

1. **先写后读**：先只开写入，不开注入，跑一天看记的质量
2. **先私聊后群聊**：群聊信息密度低，容易被无关记忆污染
3. **每加一层，留一个开关**：出问题能立刻退回上一版

## 回滚清单

| 改动 | 怎么退 |
| --- | --- |
| 检索层 | `memory.retrieval = "weight"` |
| 情绪 | 关掉情绪注入开关 |
| 日记 | 停掉定时任务即可，已写的不影响 |
| 可视化 | 删目录，桥接完全不知道它存在 |

## 周期维护

| 频率 | 做什么 |
| --- | --- |
| 每天 | 生成日记、整理记忆、体检（重复/孤儿/冲突）、备份 |
| 每周 | 看一次记忆总览，人工删掉明显错的 |
| 每月 | 看一次备份是否可恢复（只备份不验证 = 没备份） |

## 常见坑

| 现象 | 原因 | 解法 |
| --- | --- | --- |
| 一条记忆都没有 | 纪律没写进每轮提示词 | 加到唤醒提示词 |
| 记忆越记越多、提示词变长 | 没设容量上限 | 调 `archiveThreshold` |
| 她记着旧偏好不放 | 改口没作废 | 提示词加"改口先作废" |
| 换会话后像失忆 | query 用了会话历史 | query 改用桥接快照 |
| 可视化全是 `misc` | 主题词典没换 | 配 `THEMES` |
| 点太密 | 数据没筛 | 先 `--days`，再调连线阈值 |

## 安全检查（公开部署前）

- [ ] 仓库里没有任何聊天记录、日记、数据库
- [ ] 没有 QQ 号、群号、令牌、Cookie
- [ ] 示例数据全是虚构的
- [ ] 角色卡和人格设定没有一起提交
- [ ] 导出脚本只读，不反向写业务数据
