# 记忆框架与记忆海

一个跑了很久的 QQ 陪伴型机器人，记忆系统是怎么搭的。

写这份东西的理由很简单：**陪伴型 bot 的体感，八成来自"她记得"**，而"记得"这件事工程上有很多坑——记太多会污染提示词，记太少会失忆，衰减太快会显得薄情，衰减太慢会变得死板。

这套东西的原则是三条：

1. **先有遗忘，再谈记住**：不衰减的记忆库，三个月就会变成垃圾场。
2. **记忆和人格解耦**：换人格不丢记忆，换记忆不动人格。
3. **每个增强都能一键关掉**：关掉之后她应该还是原来那个她。

---

## 这套东西长什么样

```
                        ┌──────────────┐
   QQ ──▶ OneBot 网关 ──▶│   桥接程序    │──▶ 模型（DeepSeek）
                        └──────┬───────┘
                               │
              ┌────────────────┼────────────────┐
              ▼                ▼                ▼
        memory-core        日记 vault        记忆海（只读）
      事实/情绪/关系       每天一页流水      三维可视化
```

四块职责：

| 模块 | 一句话 |
| --- | --- |
| **记忆内核** | 存"结论"：事实、约定、偏好、梗，带权重和衰减 |
| **日记** | 存"过程"：每天一页，谁说了什么 |
| **检索层** | 从库里挑这一轮真正用得上的几条 |
| **记忆海** | 把上面三样画成一片能转的星海 |

为什么分"结论"和"过程"：一句"她喜欢不加糖的"是结论，值得每轮带着；"上周三晚上她说过这句话"是过程，只在被问到时才需要翻。混在一起，要么提示词爆炸，要么检索不准。

## 一条消息的完整旅程

```
1. 用户发消息
      ↓
2. 网关收下，桥接攒 6 秒（合批，避免一句话分三条触发三次推理）
      ↓
3. 拼唤醒提示词：角色 + 状态 + 最近消息 + 记忆块 + 情绪 + 节奏规则
      ↓
4. 模型决定：回什么、要不要调工具
      ↓
5. 她可能顺手调 qq_fact_append 记一条（"以后用得上"才记）
      ↓
6. 回复发回 QQ，落进最近消息快照
      ↓
7. 每天凌晨：抽关键词生成日记、整理记忆、体检、备份
```

关键点在 3 和 5：**注入什么**决定她"记得什么"，**写什么**决定她"以后能记得什么"。这两件事都得有纪律，不能让模型自由发挥。

## 实测效果（参考）

- 每天 20 条消息：记忆消耗 **0 token**（纯本地），整体约 ¥1/天
- 注入量固定 6~10 条（约 400 token），**库再大也不涨**
- 记忆容量 800 条/会话，按每天 2~3 条约一年
- 日记保留 400 天，可检索 365 天

数字来自单个部署，不代表所有场景，但量级可以参考。

## 一句话总结

**记忆不是"存得越多越好"，是"忘得越对越好"。** 这套东西一半代码在处理"怎么忘"。
