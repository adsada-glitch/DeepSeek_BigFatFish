# 04 · 记忆海

把「长期记忆 + 聊天记录 + 日记」画成一片可以旋转的三维星海。

一颗星是一件事，一根线是两件事的相似，颜色是类型。

## 它是什么，不是什么

| 是 | 不是 |
| --- | --- |
| 可视化 + 两个纯函数算法模块 | 记忆系统 |
| 只读（不写任何数据） | 存储层 |
| Canvas 2D，零依赖 | 需要 WebGL / 渲染库 |

长期记忆的**状态机**和**检索打分**确实藏在这个项目里（`memory-store.js` / `memory-retrieve.js`），可以单独拿走用——但它的主要用途是"看得见"。

## 输入数据

就三段数组：

```json
{
  "longTerm": [
    { "id": "lt-1", "text": "用户对海鲜过敏", "topic": "food",
      "kind": "fact", "confirmed": true,
      "createdAt": 1760000000000, "lastMentionAt": 1761000000000 }
  ],
  "messages": [
    { "sender": "owner", "isOwner": true, "text": "今天好累", "at": 1761000000000 },
    { "sender": "her", "isSelf": true, "text": "先坐下歇会儿", "at": 1761000060000 }
  ],
  "diaries": [
    { "date": "2026-10-27", "text": "今天很晚才回来……", "createdAt": 1761577200000 }
  ]
}
```

字段很宽松：`topic` / `kind` 缺了会自动归类；`confirmed: false` 的记忆不会画进海里。

## 场景接口

```js
import { createSceneService } from './src/scene-service.mjs';

const sea = createSceneService({ data: { longTerm, messages, diaries } });
app.get('/api/scene', (req, res) => res.json(sea.scene()));
```

`scene()` 返回：

```js
{
  ok: true,
  points: [{ id, t, kind, topic, text, weight, cluster, keywords }],
  edges: [{ a, b, score, kind }],
  stats: { total, edges, byKind, byTopic, byCluster, span }
}
```

前端只认这个结构，你可以用任何后端复刻。

## 主题：让簇名说人话

默认词典是按"学生日常"写的（考试、学校、旅游）。**一定要换成自己的**，否则一半的点会掉进 `misc`。

本项目用一个独立表覆盖它：

```js
const THEMES = [
  ['self',    '她自己', ['鲸鱼', '女仆', '体重', '可爱']],
  ['owner',   '本人',   ['主人', '带我', '答应']],
  ['sticker', '表情包', ['表情', '图片', '梗图', '斗图']],
  ['games',   '打游戏', ['上号', '开黑', '这局', '抽卡']],
  ['food',    '吃什么', ['吃', '干饭', '奶茶', '外卖', '夜宵']],
  ['tech',    '弄电脑', ['记忆', 'token', '部署', '代码', '接口']],
  ['video',   '刷视频', ['视频', '刷到', '直播']],
  ['mood',    '心情',   ['累', '烦', '开心', '难过', '想你']],
  ['sleep',   '作息',   ['睡', '困', '熬夜', '晚安']],
  ['chat',    '闲聊',   ['回消息', '在吗', '群里']]

```

顺序有讲究：越具体的放越前，一句话同时命中多个主题时，先命中的赢。

簇名通过数据里的 `topicLabels` 传给渲染器，**不用改源码**。

## 点密了怎么办

按这个顺序调，越往后越伤信息：

| 顺序 | 手段 | 效果 | 副作用 |
| --- | --- | --- | --- |
| 1 | 只看最近 N 天（`--days 14`） | 直接少一半点 | 看不到老事 |
| 2 | 过滤纯 @ 消息、太短的碎话 | 少 5~10% | 无 |
| 3 | 提高连线阈值（`minEdgeScore` 0.15→0.26） | 线少 30% | 弱关联断了 |
| 4 | 每点最多连 4 条（`maxNeighbors` 6→4） | 视觉更干净 | 同上 |
| 5 | 镜头拉远（`dist` 1200→1900） | 不挤成一团 | 点变小 |
| 6 | 上限点数（`maxPoints` 4000→900） | 兜底 | 丢最老的 |

实测：87 个点、56 条线，是"看着舒服"的密度。

## 宇宙感是怎么做的

不想上 WebGL，所以全在 Canvas 2D 里堆细节：

| 效果 | 做法 |
| --- | --- |
| 星云 | 5 团很淡的径向渐变，叠在近黑底上，只在窗口变化时重画 |
| 星场 | 620 颗，分三层深度，镜头转动时反向轻移（视差） |
| 星光 | 每颗记忆预渲染一张 64×64 光晕精灵，加色混合叠上去 |
| 闪烁 | 每颗用自己的相位（`hash(id)` 取模），避免整片同步呼吸 |
| 漂移 | 鼠标闲置 5 秒后，镜头以约 0.4°/秒自转 |

关键性能点：**光晕必须预渲染**。每帧给几百个点重建径向渐变，会直接掉到 20 帧。

## 部署形态

```
memory-sea/
├─ src/           算法 + 零依赖 HTTP 服务（默认 4173）
├─ public/        单文件渲染器
├─ data/          你的 qq.json
└─ tools/         导出脚本（把桥接状态转成三段 JSON）
```

导出脚本是**只读**的：读桥接的 `state/`，写自己的 `data/qq.json`，从不反向写。
