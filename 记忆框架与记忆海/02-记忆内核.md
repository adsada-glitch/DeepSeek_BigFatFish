# 02 · 记忆内核

零依赖单文件（`code/memory-core.mjs`），状态就是一个 JSON。

## 一条记忆长什么样

```json
{
  "id": "af3c9",
  "text": "用户对海鲜过敏",
  "tags": ["偏好"],
  "w": 2.5,
  "at": 1761000000000,
  "touch": 1761500000000,
  "hits": 3,
  "confidence": 1,
  "source": "owner"
}
```

| 字段 | 含义 |
| --- | --- |
| `text` | 一句话，20~40 字最好，超过 120 字会被截 |
| `tags` | 决定基础权重（见下） |
| `w` | 当前权重，每次衰减后回写 |
| `at` | 写入时间 |
| `touch` | 最后一次被提到的时间 |
| `hits` | 被重复提到/命中几次 |
| `confidence` | 0 = 作废；<0.5 低可信；<0.75 中等 |
| `source` | `owner`（本人说的）/ `inferred`（推断的）/ `other` |

## 基础权重

| 类别 | 命中词 | 基础分 |
| --- | --- | --- |
| 强约束 | 约定、承诺、情绪、身份、边界 | **3.0** |
| 偏好 | 偏好、作息 | **2.5** |
| 梗/人物 | 梗、表情、群友 | **1.6** |
| 事务 | 钱、余额、操作、教训、功能 | **1.3** |
| 其它 | — | **1.8** |

然后按 `confidence` 打折：

```
< 0.5   → × 0.45
< 0.75  → × 0.7
```

`confidence` 的默认值按来源给：本人说的 1.0，推断的 0.6，旁人说的 0.45。

**为什么这么设计**：模糊来源的记忆应该"淡"，但不能"没有"。打折比丢弃好——她可以在被追问时想得起来，平时不去主动提。

## 衰减：两种模式

### 线性（默认）

```
每天扣分 = 0.1（低可信 0.16），但越常想起扣得越慢：
decay = max(0.02, base / (1 + hits × 0.3))
```

一条 2.5 分的偏好，没人提：25 天后约 0。但如果 `hits=5`，衰减变 0.04/天，能撑 60 天以上。

### 艾宾浩斯

```
R = base × exp(-t / S)   S = 3 × 1.6^hits
```

每被想起一次，记忆"强度"乘 1.6——第一次 3 天，第二次 4.8 天，第五次 20 天。

**什么时候用哪个**：

| 场景 | 建议 |
| --- | --- |
| 日常聊天，信息量杂 | 线性（简单可控） |
| 想模拟"复习"效果 | 艾宾浩斯（但要把 hits 记准） |

## 沉淀（sink）

权重掉到 `1.0` 以下、且连续 3 天没回升 → 不再参与注入。

不是删除，只是"沉底"。它还在库里，被搜到时仍能捞出来。

## 相似合并

新写一条记忆时，和库里已有的比相似度（中文按字符 bigram 的 Jaccard）：

```
≥ 0.62  → 判定为"同一件事又提了一次"
         旧条目 w += 0.5（上限 6.0），hits += 1，更新 touch
         新条目不写入
```

**为什么是 0.62**：太低会把"喜欢猫"和"喜欢狗"合并（灾难）；太高会记一堆重复（提示词爆炸）。0.62 在中文短句上是个还行的分界。

**一个已知的坑**：相似合并会掩盖"改口"。

> 旧："喜欢吃甜的" → 新："现在只喝不加糖" → 相似度够高 → 旧条目被加权，而不是被纠正。

解法有两条：

1. **纪律**：提示词里写"改口时先作废旧的，再记新的"（零成本，已在用）
2. **结构**：给记忆加 `topic`，同 topic 新条目自动作废旧条目（约 20 行，需要时再加）

不要一上来就上第 2 条：自动顶替猜错时的破坏力，比手动作废大得多。

## 作废与过期

| 动作 | 实现 | 效果 |
| --- | --- | --- |
| 作废 | `confidence = 0` | 权重视为 -99，不注入、不参与合并 |
| 过期 | `validUntil = 时间戳` | 到点自动失效 |

**只标记、不删除**。作废的记录还在文件里，可以回滚，也能用来回答"我以前是不是说过这个"。

## 归档

活跃条目超过阈值（默认 120，本项目调到 **800**）时，把最淡的一批（20 条）搬进 `facts-archive.json`。

归档后**不再参与注入和检索**——这是有意的：等于"想不起来了"，但文件还在。

所以容量阈值要和注入方式配套：

| 注入方式 | 合理容量 |
| --- | --- |
| 按权重全给 80 条 | 120~200 |
| 按对话检索 6~10 条 | 500~2000 |

## 情绪

5 个标签：累 / 烦 / 开心 / 生气 / 亲近。

- 每条情绪记录带强度和原因，**3 天**后自然消退
- 桥接在收到本人私聊时自动记录，不需要模型调工具
- 注入时只给"现在的心情"，不给历史曲线

情绪不参与记忆检索——它只改语气，不改判断。

## 关系天数

`startDate` 配一个日期，注入时算"认识第 N 天"。

一个小细节：这行字对体感的影响，比任何记忆条目都大。

## 备份

- 每天备份一次，保留 7 份
- 每次写入前留快照，保留 10 份
- 备份里带上会话记录和配置——**用户不该因为程序 bug 丢数据**
